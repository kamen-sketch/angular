MENGAPA TRIASE SAJA BELUM CUKUP
-------------------------------
Triase mengelompokkan temuan berdasarkan SIFAT kodenya (positif palsu, tidak
terkirim, berguard, berkontrak). Keterjangkauan menanyakan hal berbeda: sebuah
sink yang nyata dan terkirim pun tidak berarti apa-apa bila:
  - kodenya tidak pernah masuk ke bundel aplikasi (BUNDLE GATE), atau
  - jalurnya hanya aktif di bawah konfigurasi tertentu (EXECUTION GATE), atau
  - tidak ada sumber tidak-tepercaya yang bisa mencapainya (SOURCE GATE).

Setiap sink di bawah diuji terhadap tiga gerbang itu, dengan bukti kode.

  TIDAK-TERCAPAI       tidak ada jalur pada aplikasi produksi baku
  TERCAPAI-BERSYARAT   ada jalur, tetapi butuh opt-in eksplisit pengembang
  TERCAPAI             ada jalur pada konfigurasi baku

R-01  JIT eval / new Function        ->  TIDAK-TERCAPAI (produksi AOT)
==============================================================================
  Sink : packages/compiler/src/output/output_jit_trusted_types.ts:109,125,131

  BUNDLE GATE (diverifikasi, bukan asumsi):
    Sink hanya dicapai lewat CompilerFacade. Runtime mengambilnya di
    packages/core/src/compiler/compiler_facade.ts:23
        const globalNg = global['ng'];
        if (globalNg && globalNg.ɵcompilerFacade) return globalNg.ɵcompilerFacade;
    Properti itu HANYA diisi oleh publishFacade(global) yang dipanggil di baris
    terakhir packages/compiler/src/compiler.ts:284. Artinya facade ada HANYA
    bila `@angular/compiler` benar-benar ter-import ke dalam bundel.

    Bila tidak ada, jalurnya bukan "diam-diam tidak tersanitasi" melainkan
    MELEMPAR (compiler_facade.ts:46-56) dengan pesan yang menyarankan AOT.
    Jadi kegagalannya bersifat fail-closed.

  KESIMPULAN: pada aplikasi produksi AOT (bawaan Angular CLI), `@angular/compiler`
  tidak ikut ter-bundle, sehingga sink ini TIDAK ADA di dalam artefak yang
  dikirim ke peramban. Menghitungnya sebagai temuan pada aplikasi produksi
  adalah false positive.

  TETAP RELEVAN untuk: aplikasi yang sengaja memakai platform-browser-dynamic,
  menjalankan TestBed, atau meng-import '@angular/compiler' manual.

R-02  @angular/upgrade innerHTML     ->  TERCAPAI-BERSYARAT
==============================================================================
  Sink : packages/upgrade/src/common/src/upgrade_helper.ts:254

  BUNDLE GATE  : paket `@angular/upgrade` harus dipasang dan di-import. Paket ini
                 khusus interop AngularJS; aplikasi Angular murni tidak memuatnya.
  EXECUTION GATE: harus ada komponen AngularJS yang di-upgrade (UpgradeComponent
                 atau downgradeComponent).
  SOURCE GATE  : nilainya adalah `directive.template` atau isi `templateUrl`
                 yang diambil lewat $http/$templateCache
                 (upgrade_helper.ts:96-121).

  KESIMPULAN: TERCAPAI bila aplikasi hybrid memuat template dari sumber yang
  bisa dipengaruhi penyerang (mis. templateUrl ke host pihak ketiga, atau
  template yang dirakit dari data). Untuk aplikasi Angular non-hybrid:
  TIDAK-TERCAPAI karena paketnya tidak ada di bundel.

R-04  Service Worker openWindow/navigate/fetch  ->  TERCAPAI-BERSYARAT
==============================================================================
  Sink : packages/service-worker/worker/src/driver.ts:444,451,458,461,466

  BUNDLE GATE   : service worker Angular harus diaktifkan
                  (provideServiceWorker / ServiceWorkerModule.register).
  EXECUTION GATE: pengguna harus mengizinkan notifikasi, aplikasi harus
                  berlangganan push, dan payload push harus memuat
                  `data.onActionClick[<action>]` dengan `operation` yang dikenal.
  SOURCE GATE   : payload push hanya dapat dikirim pihak yang memegang kunci
                  VAPID aplikasi - praktisnya backend aplikasi sendiri.

  MITIGASI: urlToOpen = new URL(url ?? '', registration.scope).href
            URL relatif dijamin same-origin. URL ABSOLUT tetap menang.

  KESIMPULAN: TERCAPAI-BERSYARAT dengan rantai prasyarat yang panjang. Bukan
  celah framework; namun backend push yang disusupi dapat mengarahkan klik
  notifikasi ke origin mana pun, dan `sendRequest` melakukan fetch dari dalam
  Service Worker. Layak dicantumkan dalam model ancaman aplikasi yang memakai
  push notification.

R-07  NgOptimizedImage ngSrc         ->  TERCAPAI
==============================================================================
  Sink : setHostAttribute -> renderer.setAttribute(img, 'src'|'srcset', ...)

  SOURCE GATE : `ngSrc` adalah input komponen biasa, jadi data runtime bisa
                mencapainya secara langsung.
  GUARD YANG ADA: penolakan `data:` (assertNotBase64Image) dan `blob:`
                (assertNotBlobUrl) - keduanya HANYA di ngDevMode.
  KESIMPULAN: TERCAPAI. Dampaknya bukan XSS (memuat gambar tidak mengeksekusi
  kode) melainkan permintaan jaringan ke host arbitrer: kebocoran Referer,
  pelacakan, atau SSRF pada sisi loader bila loader meneruskan URL ke server.
  Perlu dicatat: karena guard-nya dev-only, di produksi `data:`/`blob:` tidak
  ditolak - namun keduanya juga tidak berbahaya untuk `img`.

==============================================================================
CATATAN METODE
==============================================================================
Keterjangkauan di sini ditentukan dengan menelusuri pemanggil secara manual
sampai bertemu gerbang yang bisa diverifikasi di kode (properti global yang
harus diisi, provider yang harus didaftarkan, fungsi yang harus dihasilkan
compiler). Ini BUKAN analisis aliran data otomatis: ia tidak melacak nilai
melewati alias, penyimpanan sementara, atau batas asinkron.

Yang membuat kesimpulan di atas cukup kuat adalah bentuk gerbangnya - semuanya
biner dan mudah diperiksa ulang:
    ada/tidaknya `global['ng'].ɵcompilerFacade`   (R-01)
    ada/tidaknya paket di dependencies            (R-02)
    ada/tidaknya provider                         (R-03, R-04)
    asal nilai dari fungsi bikinan compiler       (R-05)
Bila salah satu gerbang berubah di versi mendatang, kesimpulannya harus dihitung
ulang - itulah sebabnya setiap gerbang dicatat beserta file:line-nya.
