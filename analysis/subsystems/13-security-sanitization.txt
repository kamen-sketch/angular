MODEL KEAMANAN ANGULAR DALAM SATU KALIMAT
------------------------------------------
Compiler menentukan KONTEKS KEAMANAN setiap binding berdasarkan pasangan
(tag, properti) dari skema DOM statis, lalu menyisipkan fungsi sanitasi yang
sesuai ke dalam kode hasil kompilasi; runtime tinggal memanggil fungsi itu tepat
sebelum menulis ke DOM.

Konsekuensinya: keamanan bergantung pada KELENGKAPAN SKEMA, bukan pada
pemeriksaan runtime yang menyeluruh. Runtime hanya menambahkan pemeriksaan ulang
untuk kasus yang tidak bisa diputuskan saat kompilasi (elemen dinamis, host
binding pada selector generik, iframe).

ENAM KONTEKS KEAMANAN (SecurityContext)
---------------------------------------
  NONE          nilai dilewatkan apa adanya
  HTML          innerHTML, outerHTML, iframe[srcdoc]      -> ɵɵsanitizeHtml
  STYLE         atribut/properti style                    -> ɵɵsanitizeStyle
  URL           a[href], form[action], *[formAction], ... -> ɵɵsanitizeUrl
  RESOURCE_URL  iframe[src], script[src], object[data],
                base[href], embed[src], link[href]        -> ɵɵsanitizeResourceUrl
  SCRIPT        konteks kode                              -> ɵɵsanitizeScript
Ditambah penanda khusus ATTRIBUTE_NO_BINDING untuk atribut yang keputusannya
harus ditunda ke runtime (dipakai ɵɵvalidateAttribute).

Perbedaan penting URL vs RESOURCE_URL: URL bisa disanitasi (protokol berbahaya
dibuang), RESOURCE_URL TIDAK BISA - memuat resource berarti mengeksekusi isinya,
jadi satu-satunya jalan adalah nilai konstan atau bypass eksplisit. Karena itu
ɵɵsanitizeResourceUrl MELEMPAR bila nilainya bukan SafeResourceUrl.

_sanitizeHtml: PERTAHANAN BERLAPIS
-----------------------------------
packages/core/src/sanitization/html_sanitizer.ts:304

  1. Parsing dilakukan di DOM INERT (`<template>` atau document hasil DOMParser),
     sehingga skrip di dalam markup tidak pernah dieksekusi (inert_body.ts).
  2. PROTEKSI mXSS: HTML di-parse berulang (maksimal 5 kali) sampai hasil
     serialisasi STABIL. Ini menutup serangan "mutation XSS" di mana koreksi
     otomatis browser mengubah markup yang tadinya jinak menjadi berbahaya
     setelah putaran parsing kedua. Bila tidak stabil setelah 5 putaran, input
     ditolak dengan error.
  3. Serialisasi ulang dengan daftar-putih tag dan atribut
     (SanitizingHtmlSerializer), bukan penghapusan berbasis daftar-hitam.
  4. Deteksi DOM CLOBBERING: `isClobberedElement` (:225) memeriksa apakah
     properti navigasi (nextSibling/firstChild) sudah "ditimpa" oleh elemen
     bernama `name="nextSibling"` dan sejenisnya - serangan klasik untuk
     menyesatkan sanitizer saat menelusuri pohon.
  5. Hasil akhir dibungkus TrustedHTML lewat trustedHTMLFromString.
  6. `finally` mengosongkan inert body agar tidak ada sisa node yang bocor.

_sanitizeUrl
------------
packages/core/src/sanitization/url_sanitizer.ts:39
Satu regex daftar-putih (SAFE_URL_PATTERN, diambil dari Closure) yang:
  - menolak `javascript:` secara eksplisit di awal pola,
  - hanya mengizinkan skema `[a-z0-9+.-]+:` atau URL relatif,
  - MELARANG `&` sebelum [/?#] agar `javascript&#58;` tidak bisa menyamarkan
    titik dua lewat entity HTML.
Nilai yang tidak lolos tidak dilempar melainkan diberi awalan `unsafe:` -
sehingga tautan menjadi tidak berfungsi alih-alih membuat halaman rusak.

TRUSTED TYPES
-------------
packages/core/src/util/security/trusted_types.ts
Policy bernama `angular` dibuat sekali (getPolicy, :38) dan dipakai untuk
membungkus hasil sanitasi. Bila aplikasi memasang CSP
`require-trusted-types-for 'script'`, browser menjadi lapisan pertahanan kedua:
penulisan string mentah ke innerHTML akan ditolak browser meski lolos dari
Angular. Ada policy terpisah untuk JIT (`newTrustedFunctionForJIT`) dan untuk
jalur bypass (`trusted_types_bypass.ts`) agar keduanya dapat diaudit terpisah.

JALUR BYPASS
------------
`SafeValueImpl` (bypass.ts:61) adalah kelas pembungkus dengan subclass per
konteks. `allowSanitizationBypassAndThrow` MELEMPAR bila tipe pembungkus tidak
cocok dengan konteks pemakaian, sehingga SafeUrl tidak bisa dipakai sebagai
SafeHtml. `unwrapSafeValue` adalah satu-satunya pintu keluar nilai mentah, dan
seluruh pemanggilnya sudah diverifikasi memanggil pemeriksaan tipe lebih dulu.

Lihat analysis/TAINT-TO-SINK.txt untuk rantai lengkap source -> sink beserta
matriks status dan daftar titik audit prioritas.
