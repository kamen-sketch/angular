MODEL DATA ROUTER
-----------------
Empat representasi yang berbeda dan sering tertukar:

  UrlTree                 hasil parse URL: pohon UrlSegmentGroup + query params
                          + fragment. Outlet bernama menjadi cabang bernama.
  RouterStateSnapshot     hasil pencocokan UrlTree dengan konfigurasi Routes;
                          pohon ActivatedRouteSnapshot (nilai statis, immutable).
  RouterState             pohon ActivatedRoute (Observable params/data/dll) yang
                          DIPAKAI ULANG antar navigasi bila rute tidak berubah.
  Routes (konfigurasi)    pohon Route yang ditulis pengembang.

PIPELINE NAVIGASI (NavigationTransitions.setupNavigations)
-----------------------------------------------------------
Seluruh navigasi adalah SATU rantai RxJS di atas `BehaviorSubject<NavigationTransition>`.
`switchMap` terluar berarti: navigasi baru otomatis MEMBATALKAN navigasi yang
sedang berjalan. Tahapannya berurutan:

  1. filter transisi null, mulai AbortController untuk navigasi ini
  2. penjagaan id: bila `this.navigationId > t.id`, navigasi ini sudah usang
     (ada komentar panjang tentang bug RxJS #7455 yang membuat penjagaan manual
     ini perlu - switchMap bisa gagal membatalkan bila navigasi baru terjadi
     sinkron di dalam handler NavigationCancel)
  3. `urlHandlingStrategy.shouldProcessUrl` - dukungan aplikasi hybrid
  4. event NavigationStart, lalu `Promise.resolve` (memaksa navigasi selalu asinkron)
  5. RECOGNIZE - cocokkan URL dengan config, terapkan redirect, muat rute lazy
  6. update URL bila mode `eager`, event RoutesRecognized
  7. `canDeactivate` -> `canActivateChild` -> `canActivate` (checkGuards)
  8. RESOLVE data (resolveData)
  9. muat komponen lazy yang diperlukan
  10. `createRouterState` - membangun pohon ActivatedRoute dengan reuse
  11. view transition (bila diaktifkan) - navigasi menunggu callback dimulai
  12. `take(1)` sebagai jaring pengaman agar transisi selalu selesai (isu #49567)
  13. titik "tidak bisa dibatalkan lagi" (`abortable = false`), event BeforeActivateRoutes
  14. AKTIVASI: pasang/lepas komponen di RouterOutlet, update URL bila mode `deferred`
  15. NavigationEnd / NavigationCancel / NavigationError, finalize

Perhatikan: guard dan resolver berjalan SEBELUM RouterState dibuat; itulah
sebabnya guard menerima `ActivatedRouteSnapshot`, bukan `ActivatedRoute`.

RECOGNIZER
----------
`Recognizer` menelusuri konfigurasi secara rekursif:
  processSegmentGroup -> processChildren -> processSegment ->
  processSegmentAgainstRoute -> matchSegmentAgainstRoute
Di setiap simpul ia mencoba mencocokkan `path` (termasuk parameter `:id` dan
wildcard `**`), menjalankan `canMatch` guard, menangani `redirectTo`
(`expandSegmentAgainstRouteUsingRedirect`), dan memuat `loadChildren` lewat
`RouterConfigLoader`. Rute dengan path kosong ditangani khusus - `hasEmptyPathConfig`
dan `sortActivatedRouteSnapshots` menjaga urutan hasil agar deterministik.

Kegagalan pencocokan dilempar sebagai `NoMatch`; redirect absolut sebagai
`AbsoluteRedirect`; keduanya ditangkap di lapisan atas dan diterjemahkan menjadi
error/navigasi baru.

GUARD
-----
`checkGuards` menjalankan guard dalam urutan yang penting:
  1. `canDeactivate` dari rute terdalam ke terluar (yang akan ditinggalkan)
  2. `canActivateChild` dari terluar ke terdalam
  3. `canActivate`
Setiap guard boleh mengembalikan boolean, UrlTree (redirect), atau Observable/
Promise dari keduanya; `redirectIfUrlTree` menerjemahkan UrlTree menjadi
pembatalan navigasi + navigasi baru. `runCanLoadGuards` dan `runCanMatchGuards`
dipakai pada fase recognize, bukan di sini.

RESOLVER
--------
`resolveData` meratakan pohon rute lalu menjalankan resolver setiap simpul,
menghormati `runGuardsAndResolvers` dan strategi pewarisan parameter
(`paramsInheritanceStrategy`). Hasilnya disimpan ke snapshot sebelum aktivasi.

REUSE ROUTE STATE
-----------------
`createRouterState` + `createOrReuseChildren` memutuskan ActivatedRoute mana yang
dipakai ulang berdasarkan `RouteReuseStrategy.shouldReuseRoute`. Inilah alasan
komponen tidak dibuat ulang saat hanya parameter yang berubah - dan alasan
`ActivatedRoute.params` harus dibaca sebagai Observable, bukan sekali saja.

MEMBANGUN URL
-------------
`createUrlTree*` menerjemahkan array perintah (`router.navigate(['../x', {id: 1}])`)
menjadi UrlTree: `computeNavigation` menghitung berapa tingkat naik (`..`) dan
apakah perintah bersifat absolut, `findStartingPositionForTargetGroup` mencari
segmen awal, lalu segmen baru disusun dengan mempertahankan matrix params dan
outlet bernama.
