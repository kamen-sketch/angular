DUA API, SATU MODEL
-------------------
Reactive forms dan template-driven forms memakai MODEL YANG SAMA
(`AbstractControl`, `FormControl`, `FormGroup`, `FormArray`). Perbedaannya hanya
siapa yang membuat model:
  - Reactive: pengembang membuat model, directive (`formControl`,
    `formControlName`, `formGroup`) menempel padanya.
  - Template-driven: directive `ngModel`/`ngForm` MEMBUAT model secara implisit,
    secara asinkron (lewat `resolvedPromise` microtask) agar struktur grup
    sempat terbentuk.

Jembatan ke elemen DOM adalah `ControlValueAccessor` - antarmuka empat metode
(`writeValue`, `registerOnChange`, `registerOnTouched`, `setDisabledState`)
dengan implementasi bawaan per jenis input (default/text, checkbox, number,
radio, range, select, select-multiple). `selectValueAccessor` memilih accessor
mana yang dipakai ketika beberapa cocok, dengan prioritas: custom > bawaan
khusus > default.

SIKLUS VALIDASI (updateValueAndValidity)
-----------------------------------------
Ini jantung paket forms. Urutannya:

  1. `_setInitialStatus()`  -> DISABLED bila semua anak disabled, selain itu VALID
  2. `_updateValue()`       -> hitung ulang nilai agregat (khusus grup/array)
  3. bila enabled:
       - batalkan langganan validator async yang masih berjalan
       - jalankan validator sinkron -> `errors`
       - `_calculateStatus()` -> VALID | INVALID | PENDING | DISABLED
       - bila hasilnya VALID/PENDING, jalankan validator async (status PENDING)
  4. emit `ValueChangeEvent` + `StatusChangeEvent` ke `_events`, dan
     `valueChanges` + `statusChanges` (EventEmitter lama) - kecuali
     `emitEvent: false`
  5. bila bukan `onlySelf`, PROPAGASI KE ATAS: `parent.updateValueAndValidity()`

Poin yang sering menjadi sumber bug aplikasi:
  - Perubahan menyebar KE ATAS, tidak ke bawah. Untuk memvalidasi ulang seluruh
    pohon ke bawah ada `_updateTreeValidity` (dipakai saat form di-setup).
  - `emitEvent: false` hanya menekan emisi, TIDAK menekan perhitungan.
  - Status DISABLED bukan bagian dari valid/invalid: kontrol disabled tidak ikut
    dalam nilai `value` (hanya muncul di `getRawValue()`).
  - `setErrors()` menulis error secara manual lalu memanggil
    `_updateControlsErrors`, yang menyebarkan status ke leluhur tanpa menjalankan
    ulang validator.
  - Validator async yang lama dibatalkan setiap kali `updateValueAndValidity`
    berjalan (`_cancelExistingSubscription`), dengan penanda `shouldHaveEmitted`
    agar emisi status tetap konsisten.

`updateOn: 'change' | 'blur' | 'submit'` diselesaikan lewat `_updateOn` yang
diwarisi dari leluhur bila tidak diset; directive value accessor memutuskan kapan
memanggil `setValue` berdasarkan nilai ini.

STRUKTUR KONTROL
----------------
  FormControl  - nilai tunggal; menyimpan `_pendingValue`, `_pendingChange`,
                 `_pendingDirty`, `_pendingTouched` untuk mode updateOn non-change.
  FormGroup    - Map nama->kontrol; `_updateValue` menyusun objek dari anak yang
                 enabled; `assertControlPresent` memberi error jelas bila
                 setValue tidak menyertakan semua kunci.
  FormArray    - array kontrol dengan API push/insert/removeAt/clear.
  FormRecord   - FormGroup dengan kunci dinamis dan tipe seragam.

`FormBuilder` (dan `NonNullableFormBuilder`) hanyalah pabrik ergonomis di atas
konstruktor tersebut; `UntypedFormBuilder` mempertahankan perilaku pra-typed-forms.

VALIDATOR
---------
`Validators` menyediakan validator statis (required, min, max, minLength,
maxLength, pattern, email, nullValidator) plus `compose`/`composeAsync` yang
menggabungkan beberapa validator menjadi satu dan menggabungkan objek error.
Versi directive-nya (`RequiredValidator`, `MinLengthValidator`, dst) ada di
`directives/validators.ts` dan mendaftarkan diri lewat multi-provider
NG_VALIDATORS/NG_ASYNC_VALIDATORS.

`ng_control_status.ts` memetakan status model ke kelas CSS
(ng-valid/ng-invalid/ng-pending/ng-pristine/ng-dirty/ng-touched/ng-untouched)
lewat host bindings.
