POSISI LAPIS INI
----------------
Subsistem 01 memberi mesin reaktif murni. Subsistem ini adalah PEMBUNGKUS
Angular di atasnya: menambahkan DI, siklus hidup view, penjadwalan, dan
integrasi dengan change detection.

    primitives/signals            ->  src/render3/reactivity  ->  API publik
    (createSignal/createComputed)     (signal/computed/effect)    (signal(), effect())

DUA JENIS EFFECT - PERBEDAAN YANG PALING SERING SALAH DIPAHAMI
---------------------------------------------------------------
`effect()` menghasilkan salah satu dari dua node, ditentukan oleh apakah ada
`ViewContext` di injector saat pemanggilan:

  VIEW EFFECT (component effect)
    - dibuat di komponen/directive (atau service milik komponen).
    - disimpan di `lView[EFFECTS]`.
    - saat kotor: set `HasChildViewsToRefresh` + `markAncestorsForTraversal`,
      lalu beri tahu scheduler (NotificationSource.ViewEffect).
    - DIJALANKAN SEBAGAI BAGIAN DARI CHANGE DETECTION view tersebut
      (`runEffectsInView` dipanggil di dalam `refreshView`), sehingga aman
      membaca input signal dan memanipulasi view.
    - ikut hancur otomatis saat view dihancurkan.

  ROOT EFFECT
    - dibuat di luar pohon komponen (mis. service `providedIn:'root'`).
    - dikelola `ZoneAwareEffectScheduler`, dijalankan sebagai microtask lewat
      `ApplicationRef.synchronizeOnce` (flag RootEffects) - TANPA kaitan dengan
      pohon komponen.

Keduanya berbagi `EFFECT_NODE` yang menyediakan `run()` dan `cleanup()`.
Detail penting di `run()`: `setIsRefreshingViews(false)` dipasang sementara,
supaya `markForCheck()` yang dipanggil DI DALAM effect benar-benar sampai ke
komponen bersangkutan (lihat pembahasan bit Dirty vs RefreshView di subsistem 03).

`cleanup()` menjalankan fungsi cleanup terdaftar dengan `setActiveConsumer(null)`
dan selalu mengosongkan daftar meski terjadi error.

`runEffectsInView` melakukan flush berulang: effect bisa mengotori effect lain,
jadi ia berputar selama masih ada effect kotor DAN view masih bertanda
`HasChildViewsToRefresh`. Setiap effect dijalankan kembali di zone tempat ia
dibuat (`effect.zone`), penting untuk aplikasi berbasis Zone.

`ZoneAwareEffectScheduler` menyimpan antrean TERPISAH PER ZONE (`Map<Zone, Set>`).
Urutan eksekusi dijamin FIFO di dalam satu zone, tapi tidak antar-zone. Ada
pengaman: jika `dirtyEffectCount` tidak sinkron dengan flag effect, counter
dipaksa nol agar tidak berputar selamanya.

INPUT SIGNAL
------------
`input()` membuat node berbasis `INPUT_SIGNAL_NODE` yang merupakan SignalNode
biasa plus:
  - `transformFn` (opsi `transform`) - selalu di-set walau undefined, dengan
    komentar perf eksplisit agar bentuk objek tetap monomorfik di V8.
  - sentinel `REQUIRED_UNSET_VALUE` untuk `input.required()`: membaca sebelum
    nilai tersedia melempar NG0950.
Penulisan nilai TIDAK dilakukan lewat API publik - runtime menulisnya lewat
`applyValueToInputField`/`setDirectiveInput` saat binding berubah. Jadi input
signal adalah signal read-only dari sudut pandang komponen, tapi writable dari
sudut pandang runtime.

MODEL SIGNAL
------------
`model()` = InputSignalNode + `OutputEmitterRef`. `set`/`update` menulis nilai
LALU meng-emit ke output pasangannya (nama output = `<name>Change`), sehingga
two-way binding `[(x)]` bekerja tanpa mekanisme khusus. `asReadonly()` memakai
`signalAsReadonlyFn` yang di-bind ke getter.

OUTPUT
------
`output()` mengembalikan `OutputEmitterRef` - bukan RxJS Subject. Ia menyimpan
daftar listener sederhana, terikat `DestroyRef` sehingga langganan otomatis
dilepas saat komponen hancur, dan `emit()` menolak emit setelah destroy.
`removeNullValues` membersihkan slot listener yang sudah dilepas.

QUERY BERBASIS SIGNAL (viewChild/contentChild/viewChildren/contentChildren)
--------------------------------------------------------------------------
Implementasinya elegan: query signal adalah COMPUTED biasa yang membaca sebuah
"dirty counter" signal internal (`node._dirtyCounter`). Runtime tinggal menaikkan
counter itu ketika hasil query mungkin berubah (view selesai dibuat, view
disisipkan/dihapus), dan computed akan menghitung ulang hasilnya.

Optimasi: `_flatValue` menyimpan hasil rata terakhir sehingga manipulasi view
yang TIDAK mengubah hasil akhir tidak membuat computed dianggap berubah
(pembanding kesetaraan bekerja di level hasil, bukan di level notifikasi).
`bindQueryToSignal` menghubungkan node signal ke slot QueryList di LView.

Varian required melempar NG0951 bila hasilnya undefined.

API LAIN
--------
- `signal()`/`computed()`/`linkedSignal()` di `render3/reactivity` hanya
  membungkus fungsi primitives dan menambahkan `debugName`, `asReadonly`,
  serta hook DevTools.
- `untracked()` dan `assertNotInReactiveContext` menjaga batas konteks reaktif;
  `effect()` menolak dipanggil dari dalam konteks reaktif.
- `ɵunwrapWritableSignal` adalah utilitas kompilasi untuk two-way binding.
