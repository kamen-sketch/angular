SUBSISTEM 06 :: Compiler - dari HTML ke fungsi template
Lokasi   : packages/compiler/src/**
Status   : DIANALISIS PADA TINGKAT ALUR + FUNGSI KUNCI
           (72 phase pipeline dipetakan sebagai daftar, bukan satu per satu)
==============================================================================

RANTAI TRANSFORMASI LENGKAP
---------------------------
Template Angular melewati lima representasi berbeda sebelum menjadi JavaScript:

  1. STRING HTML
        |  lexer.ts (tokenize)
  2. TOKEN
        |  ml_parser/parser.ts (Parser/HtmlParser)
  3. AST HTML  (html.Element, html.Attribute, html.Block, html.Expansion/ICU)
        |  r3_template_transform.ts (HtmlAstToIvyAst)
  4. AST R3 (t.Element, t.Template, t.IfBlock, t.ForLoopBlock, t.DeferredBlock)
        |  template/pipeline/src/ingest.ts
  5. IR (Intermediate Representation) berbasis OPERASI
        |  72 phase transformasi (emit.ts `phases`)
  6. AST OUTPUT (output_ast.ts) -> teks JavaScript / TypeScript

Ekspresi di dalam template ({{...}}, [x]="expr") punya jalur parser sendiri:
`expression_parser/lexer.ts` + `expression_parser/parser.ts` menghasilkan AST
ekspresi Angular (bukan AST TypeScript), lalu `convertAst` di ingest.ts
menerjemahkannya ke IR.

MENGAPA ADA IR (arsitektur "template pipeline")
-----------------------------------------------
Versi lama compiler membangun output secara langsung saat menelusuri AST.
Arsitektur sekarang memakai IR berisi daftar OPERASI (create ops dan update ops)
per view, lalu menjalankan puluhan phase kecil yang masing-masing melakukan SATU
transformasi. Keuntungannya: tiap phase bisa diuji sendiri, urutan transformasi
menjadi eksplisit, dan optimasi (chaining, pure function extraction, const
collection) tinggal menjadi phase tambahan.

Struktur inti:
  - `CompilationJob` : satu unit kompilasi (komponen atau host binding).
  - `ViewCompilationUnit` : satu view (root atau embedded); punya dua daftar
    operasi: `create` dan `update` - persis dua fase runtime di subsistem 04.
  - `XrefId` : identitas simbolik antar-operasi, diselesaikan menjadi indeks
    slot nyata pada phase-phase akhir.

URUTAN PHASE (emit.ts, dijalankan oleh `transform`)
---------------------------------------------------
Dikelompokkan menurut tujuan (nama sesuai berkas di phases/):

  NORMALISASI AWAL
    resolveForeignContent, removeContentSelectors, optimizeRegularExpressions,
    parseHostStyleProperties, emitNamespaceChanges
  I18N (bagian 1)
    propagateI18nBlocks, wrapI18nIcus, createI18nContexts
  SPESIALISASI BINDING
    deduplicateTextBindings, specializeStyleBindings, specializeBindings,
    specializeControlProperties, convertAnimations, extractAttributes,
    parseExtractedStyles, removeEmptyBindings, collapseSingletonInterpolations
  PENGURUTAN & PEMBENTUKAN STRUKTUR
    orderOps, generateConditionalExpressions, createPipes,
    configureDeferInstructions, insertIncrementalHydrationRuntime,
    createVariadicPipes, generateArrowFunctions, generatePureLiteralStructures,
    generateProjectionDefs, generateLocalLetReferences, generateVariables,
    saveAndRestoreView, deleteAnyCasts
  RESOLUSI NAMA & KONTEKS
    resolveNames, resolveContexts, resolveDollarEvent, liftLocalRefs,
    mergeNextContextExpressions, expandSafeReads
  I18N (bagian 2)
    convertI18nText, convertI18nBindings, applyI18nExpressions,
    extractI18nMessages, resolveI18nElementPlaceholders,
    resolveI18nExpressionPlaceholders, resolveI18nAttrSanitizers,
    assignI18nSlotDependencies, removeI18nContexts, collectI18nConsts,
    removeUnusedI18nAttributesOps
  ALOKASI SLOT & OPTIMASI AKHIR
    collectElementConsts, collectConstExpressions, extractPureFunctions,
    generateAdvance, nameFunctionsAndVariables, reify, chain,
    collapseEmptyInstructions, attachSourceLocations

Dua phase paling menentukan bentuk output:
  - `generateAdvance` menyisipkan `ɵɵadvance(n)` berdasarkan selisih slot antar
    operasi update - inilah pasangan compile-time dari mekanisme "selected index"
    di runtime (subsistem 04).
  - `reify` mengubah operasi IR abstrak menjadi pemanggilan instruksi konkret
    (`ɵɵelementStart`, `ɵɵproperty`, ...); setelah phase ini semua operasi harus
    sudah berupa `Statement`, dan `emitView` melempar AssertionError bila tidak.
  - `chain` menggabungkan instruksi berurutan yang sama menjadi rantai
    (`ɵɵelementStart(...)(...)`) untuk memperkecil ukuran bundel.

INGEST: DARI AST R3 KE IR
-------------------------
`ingestComponent` membangun `ComponentCompilationJob` lalu `ingestNodes`
menelusuri AST. Setiap bentuk sintaks punya fungsi ingest sendiri:
elemen, template, ng-content, teks (statis vs terinterpolasi), @if, @switch,
@for, @defer (+ trigger), ICU, dan `@let`. Fungsi `convertAst` menerjemahkan AST
ekspresi Angular ke ekspresi IR, menangani hal-hal seperti safe navigation
(`a?.b`), pipe, dan `$event`.

`ingestHostBinding` menangani host bindings sebagai job terpisah - itulah sebabnya
ada `Kind.Host` / `Kind.Tmpl` / `Kind.Both` pada daftar phase.

DEFINISI KOMPONEN/DIRECTIVE
---------------------------
`compileComponentFromMetadata` dan `compileDirectiveFromMetadata` menyusun objek
literal yang menjadi `ɵcmp`/`ɵdir`: selectors, inputs, outputs, features,
hostBindings, contentQueries, viewQuery, template fn, styles, encapsulation,
dan daftar dependensi. `addFeatures` menambahkan feature seperti
`ɵɵInheritDefinitionFeature`, `ɵɵNgOnChangesFeature`, `ɵɵProvidersFeature`,
`ɵɵHostDirectivesFeature` - yaitu fungsi runtime yang menambal definisi.

`parseHostBindings`/`verifyHostBindings` mengurai objek `host: {...}` menjadi
atribut, properti, dan listener, sekaligus melarang binding event di tempat yang
tidak sah.

`compileStyles`/`encapsulateStyle` memroses CSS komponen; `shadow_css.ts`
mengimplementasikan emulated encapsulation (menambahkan atribut _ngcontent-*/
_nghost-*).

MODE KOMPILASI
--------------
Ada tiga: FULL (definisi lengkap), PARTIAL (untuk pustaka - menghasilkan
`ɵɵngDeclareComponent` yang nanti diterjemahkan linker di `render3/partial/`),
dan LOCAL (kompilasi tanpa informasi lintas-berkas). `compileComponentFromMetadata`
memilih jalur berdasarkan `meta.isStandalone`, dependensi, dan mode.
