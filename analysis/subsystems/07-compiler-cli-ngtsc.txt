APA ITU ngtsc
-------------
ngtsc adalah "TypeScript compiler plugin" Angular. Ia TIDAK mem-parse
TypeScript sendiri - ia memakai `ts.Program` milik TypeScript, membaca metadata
dekorator lewat refleksi AST, memanggil `packages/compiler` untuk menghasilkan
kode, lalu menyuntikkan hasilnya sebagai transformer saat emit.

Alur besar (NgtscProgram):

  ts.Program  ->  NgCompiler.analyze  ->  resolve  ->  typeCheck  ->  emit
                        |                    |            |            |
                   TraitCompiler        scope/registry  TemplateTypeChecker
                                                             |
                                              berkas .ngtypecheck.ts bayangan

DIREKTORI PENTING
-----------------
  annotations/     handler per dekorator (component, directive, ngModule, pipe,
                   injectable) - inti logika "baca metadata lalu kompilasi"
  transform/       TraitCompiler + transformer TypeScript yang menyuntik ɵcmp dll
  scope/           LocalModuleScopeRegistry: directive/pipe apa yang terlihat
                   oleh sebuah komponen (NgModule maupun standalone imports)
  metadata/        registry metadata directive/pipe/NgModule (lokal dan dari .d.ts)
  reflection/      abstraksi pembacaan kelas/dekorator dari AST TypeScript
  partial_evaluator/ evaluator statis untuk nilai dekorator (mengeksekusi
                   ekspresi TS secara simbolik: objek, array, enum, spread, dll)
  typecheck/       pembuatan Type Check Block (TCB) untuk memeriksa template
  incremental/     graf dependensi + penentuan berkas mana yang perlu di-emit ulang
  imports/         strategi penulisan import (relatif, absolut, unified modules)
  cycles/          deteksi impor melingkar antar berkas hasil generate
  shims/           berkas bayangan (.ngfactory, .ngsummary, .ngtypecheck)
  perf/            instrumentasi fase kompilasi
  docs/, indexer/, xi18n/, hmr/, sourcemaps/, validation/, entry_point/

MODEL "TRAIT" (inti yang perlu dipahami)
----------------------------------------
Setiap kelas yang cocok dengan sebuah handler menjadi TRAIT dengan status yang
berpindah maju: Pending -> Analyzed -> Resolved -> (Skipped bila error).
`TraitCompiler` menyimpan `ClassRecord` per kelas dan menjalankan tahap-tahap
`DecoratorHandler`:

  detect      apakah handler ini menangani kelas tsb (baca dekorator)
  preanalyze  opsional & asinkron - dipakai untuk memuat templateUrl/styleUrls
  analyze     ekstraksi metadata; WAJIB MURNI/TANPA EFEK SAMPING karena pada
              build inkremental tahap ini boleh dilewati untuk berkas yang tidak
              berubah (hasilnya diambil dari cache)
  register    efek samping (mendaftarkan metadata ke registry) - selalu dijalankan
  resolve     penyelesaian lintas-berkas (scope directive/pipe, cek siklus)
  typeCheck   menyumbang Type Check Block untuk template
  compileFull/compilePartial/compileLocal  menghasilkan ekspresi definisi

Pemisahan analyze (murni) vs register (efek samping) inilah yang membuat build
inkremental benar; komentar di `transform/src/api.ts` menyatakannya eksplisit.

`HandlerPrecedence` mengatur interaksi bila beberapa handler cocok pada kelas
yang sama (mis. `@Component` PRIMARY mengalahkan `@Injectable` SHARED).

MODE KOMPILASI
--------------
`makeCompilation` menentukan mode:
  FULL     - aplikasi biasa; definisi lengkap dengan referensi langsung.
  PARTIAL  - untuk publikasi pustaka; menghasilkan `ɵɵngDeclare*` yang stabil
             antar versi, diterjemahkan kemudian oleh linker.
  LOCAL    - "experimental-local"/emitDeclarationOnly; kompilasi per berkas tanpa
             informasi lintas-berkas (untuk build paralel cepat).
Catatan menarik: kompilasi `@angular/core` SELALU FULL, karena core tidak perlu
indireksi kompatibilitas terhadap dirinya sendiri.

STRATEGI IMPOR (ReferenceEmitter)
---------------------------------
Saat compiler harus menulis referensi ke kelas lain (mis. daftar dependensi
komponen), ia memilih cara menulis import lewat rantai strategi:
  LocalIdentifierStrategy (sudah ada di berkas ini) ->
  AbsoluteModuleStrategy (import dari paket npm) ->
  LogicalProjectStrategy / RelativePathStrategy (import relatif dalam proyek)
Bila host mendukung `fileNameToModuleName` (Bazel/google3), dipakai
UnifiedModulesStrategy. Ini juga tempat penanganan `rootDirs`.

TYPE CHECKING TEMPLATE
----------------------
Template diperiksa dengan cara menghasilkan berkas TypeScript bayangan berisi
"Type Check Block": kode TS palsu yang mereplikasi ekspresi template beserta
tipe konteksnya, lalu dibiarkan TypeScript sendiri yang melaporkan error.
Diagnostik hasilnya dipetakan kembali ke posisi asli di template lewat
sourcemap internal. `getTypeCheckingConfig` menerjemahkan opsi
(`strictTemplates`, `strictNullInputTypes`, `strictDomLocalRefTypes`, ...)
menjadi konfigurasi pembangkitan TCB.

INKREMENTAL
-----------
`IncrementalCompilation` menyimpan graf dependensi berkas (termasuk dependensi
resource seperti templateUrl/styleUrls) dan hasil analisis sebelumnya. Empat
fungsi "ticket" di compiler.ts menentukan bagaimana kompilasi baru dimulai:
dari nol, dari compiler sebelumnya, dari state tersimpan, atau hanya karena
resource berubah (jalur cepat untuk perubahan HTML/CSS saja).
